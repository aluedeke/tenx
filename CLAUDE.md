# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

`tenx` is a CLI + TUI tool (Rust) that manages multi-repo "workspaces" and "tasks". A workspace holds one or more bare git repos; a task is a named unit of work that creates a git worktree (on a branch matching the task's slug) in each of the workspace's repos, then opens a claude/nvim/shell window for that task inside the single global **tmux** session. It also drives a Claude Code integration layer of its own (skills, plus live task state read from Claude Code's session registry) and a `standup` command that summarizes recent Claude Code activity — so this tool is itself part of the harness a Claude Code session runs inside when working in a `tenx`-managed task.

This is the **v2 rebuild** (v1 ran on zellij with two wasm plugins; `ARCHITECTURE.md` is the human-oriented map of the current design, `README.md` the user-facing one). The reasons for the switch, in one line each: tmux `display-popup` is per-client so one ratatui overlay serves every surface; tmux control mode is the proven protocol for a future native client; `monitor-bell` gives a generic attention channel; headless tmux makes end-to-end tests possible.

## Commands

```sh
cargo build --release          # build
cargo run -- <args>            # e.g. `cargo run -- task list`
make test                      # cargo test + clippy -D warnings, both crates
make install                   # cargo install --path . (nothing else to place)
make screenshot                # re-render docs/overlay.svg from fixtures (src/tui/overlay/screenshot.rs)
tenx internal tmux-conf        # print the generated tmux config (hidden command)
```

CI (`.github/workflows/ci.yml`) runs build/test/clippy on macOS and Ubuntu. `Cargo.lock` is checked in.

## Crates

- **`tenx-core/`** — pure logic, no `Command`, no filesystem beyond what a caller hands in: `status` (`TaskStatus`/`TaskGroup`/`TaskState`, `Session`, `resolve_task_state`), `slug` (`slugify`), `time` (`format_age`, `parse_duration`), `sweep` (`sweep_reason`, `DEFAULT_SWEEP_AFTER`), `taskmd` (`render_task_md`, `display_name`, `with_title`). **Unit tests live here** — put any new decision logic here first, then call it from the binary. `workspace::` re-exports the status types so call sites keep their paths.
- **`tenx`** (root) — the binary: CLI, overlay, watcher.

## Architecture (binary)

Independent layers wired together by `main.rs`'s CLI dispatch; each layer only knows about the layer(s) below it:

- **`cli/`** — clap-based argument parsing (`mod.rs`) plus one file per subcommand group: `init.rs`, `repo.rs`, `task.rs`, `standup.rs`, `hooks.rs`, `watch.rs`, `secrets.rs`, `notify.rs`. The overlay calls directly into these functions (`cli::task::{new_in,open_in,rm_in,set_repos_in}`, `cli::repo::add_in`, `cli::secrets::fulfill_in`) instead of duplicating logic. Every mutating command also takes `--ws-dir` for scripts/front ends that don't run inside the workspace. A hidden `internal` group holds plumbing (`tmux-conf` now; tmux hook targets in Phase 2).
- **`workspace/`** — the on-disk model. A *workspace* is a directory with a `config.toml` (name, layout script path, list of repos, optional `age_identity`) and a `tasks/` subdirectory; each subdirectory under `tasks/` is a *task*. `workspace::find()` walks up from cwd looking for `config.toml`. Global user config lives at `~/.config/tenx/config.toml` (just a `bare_dir` override). The workspace *registry* is one file per workspace under `~/.config/tenx/workspaces.d/<name>-<pathhash>.toml` — registration is a single atomic file write; pruning is a per-file delete. Config writes are atomic (write to `.toml.tmp`, then rename). `workspace/claude.rs` reads Claude Code's session registry (filesystem + pid checks); what a session list *means* is `tenx_core::status`.
- **`git/`** — shells out to the system `git` for everything (bare clone, fetch, worktree add/remove, default-branch detection) so SSH agent / credential helpers behave like the user's own `git`. Bare repos live under `<workspace>/.bare/<name>.git` by default. `ensure_synced()` clones or fetches — the entry point task creation uses.
- **`progress.rs`** — a threaded spinner for clone/fetch/worktree operations.
- **`live.rs`** — the per-task `.tenx-live.json` cache of external facts: listening ports (window pane pids → `ps` descendants → `lsof` listeners) and PRs (`gh pr view --json`). Only `tenx watch` writes it (`refresh_live`: ports every tick; PRs staggered, on a helper thread, 2 min TTL active / 30 min parked, ≤2 lookups per tick); the overlay, `task_json` and the status line only read it. Parsing and chip text are `tenx_core::live`. `tenx internal ports` prints the current port map.
- **`tmux/`** — the session layer. tenx runs its **own tmux server** on a dedicated socket (`tmux -L tenx`, `TENX_TMUX_SOCKET` overrides for tests), started against a generated `~/.config/tenx/tmux.conf` (`render_config`: theme from `palette.rs`, blanked window list, `status-left` from the `@tenx_status` window option, `status-right` from the global `@tenx_right`, `monitor-bell on`, `bind -n C-w display-popup -E … tenx overlay`). The user's `~/.tmux.conf` is untouched. **Windows are tasks**, named by slug (immutable, unique within a workspace) and tracked by their stable `@id`, cached per task in `.tenx-window-id` as a fast path only — `find_window` by name is the truth. `open_task_window` builds the default layout (claude left; nvim on `TASK.md` top-right; shell bottom-right) with `new-window`/`split-window`, or runs the workspace's `layout` script with `TENX_WINDOW`/`TENX_SLUG`/`TENX_TASK_DIR`/`TENX_WS_DIR`/`TENX_CLAUDE_CMD`/`TENX_TMUX` in the environment. `attach_or_create` execs `new-session -A` with the home window running `tenx overlay --home` in a restart loop. tmux reads the config only at server start — after changing `render_config`, `tmux -L tenx kill-server` then `tenx`.
- **`tui/`** — the ratatui overlay (`overlay.rs`, plus `mouse.rs`). **The only overlay implementation.** Lists every task across every registered workspace, sectioned by `TaskGroup` (secrets pending → waiting for input → working → inactive), fuzzy-filtered, with Telescope-style modes (search field = Insert; list row = Normal: `n` new, `a` add repo, `r` rename, `e` edit repos, `x` close window, `u` unlock secrets, `dd` delete, `Enter`/`o`/`l` jump, `:` commands incl. `:cancel` to withdraw secrets requests). Two modes: *home* (`--home`, the session's permanent window 0 — jump selects the task's window and stays; quit keys are swallowed) and *popup* (`tenx overlay` under `display-popup -E` — exits after a jump, tmux closes the popup). Run from a plain terminal outside tmux, a jump records an `AttachTarget` and `run()` attaches after teardown. The home instance runs a rate-limited background sweep on focus-gained. `Overlay::empty` builds one with no I/O; `overlay/screenshot.rs` (test-only) fills it with fixture rows, renders through ratatui's `TestBackend`, asserts every section and chip kind appears, and with `TENX_SCREENSHOT` set writes the buffer as `docs/overlay.svg` — the README image is generated from the real widgets, never from a real workspace.

## Key flows to understand together

- **No-argument invocation** (`open()` in `main.rs`): self-heals the registry if cwd is in a workspace, checks `tmux -V ≥ 3.3` (the generated config uses `display-popup -T` and popup styling), ensures the watcher, then: inside the tenx session → run the overlay in this pane; inside some *other* tmux server → error with `tmux::foreign_client_hint()` (no cross-server switch exists; nesting is a trap); outside tmux → `attach_or_create` (exec). Over SSH, `tenx` does the same thing — same server, same session.
- **Task creation** (`cli::task::new_in`): slugifies the name (`tenx_core::slug::slugify` — lowercase, `[a-z0-9]` only, runs collapsed to `-`; an empty slug is an error) for the directory/branch/window name but keeps the original as the display name. Writes `TASK.md` from `tenx_core::taskmd::render_task_md`, retires any old tenx hooks in the workspace's `.claude/`, symlinks `tasks/<slug>/.claude → ../../.claude`, then per repo: `ensure_synced` + `git worktree add -B <slug>` off the freshly-fetched default branch. Then (unless `--no-open`, and only if the server is running) opens the window and records its id.
- **A task's repo set is derived from disk, never recorded**: `discover_task` scans for subdirectories containing a `.git` *file*. `task add-repo`/`rm-repo` (imperative) and `task set-repos` (declarative, adds before removes) share `ensure_repo_worktree` with creation. Detaching removes the worktree *and* its branch and does not `--force` unless asked — git's refusal to drop a dirty worktree is the safety net.
- **Task display name vs. slug**: `display_name` is `TASK.md`'s first heading (fallback: directory name); slug/branch/directory/window all use the slug. `task rename` rewrites only the heading.
- **Task names typed by a human** (`task open/rm/pin/…` without `--ws-dir`) resolve via `cli::task::slug_for`: the exact directory name if such a task exists (tasks created before `slugify` tightened may have punctuation in their names), else the slugified name. `task new` also refuses a title that matches an existing task's display name, and the slug `home` (the overlay's window).
- **Task open** (`open_in`): `find_window(slug)` → `select-window` (this changes the *session's* current window, so it works from any client and from outside one); else create the window, passing `--continue` to claude only if `has_claude_conversation` finds a transcript for that exact directory (otherwise claude exits 1 and the pane vanishes).
- **Sweep / pin** (`cli::task::sweep_candidates` + `tenx_core::sweep::sweep_reason`): closes windows nobody is waiting on — never the current window, a pinned task (`.tenx-pinned`), or a `Blocked`/`Working` task; `Idle` immediately, `Done` after `--after` (default 8h). Reopening recreates the window and `--continue` picks the conversation back up.
- **Claude Code integration is bidirectional**: `tenx init` optionally installs `/tenx` (`src/cli/skills/tenx.md`) and `/standup` skills into `.claude/skills/`. A task's *state* comes from **Claude Code's session registry** (`~/.claude/sessions/<pid>.json`, pid-checked **and scoped to sessions whose pid descends from a pane of the tenx tmux server** — `tenx_core::status::in_panes`; the registry is per user, so a Claude in a plain terminal or an abandoned multiplexer would otherwise pin its task's status) merged with its **tmux window's bell flag** (`tmux::signals()`, keyed by slug): any `waiting` → `Blocked` (with Claude's reason), else a bell → `Signaled` (🔔 — any process in any pane can `printf '\a'`; tmux clears it when the window is visited), else any `busy` → `Working`, else a quiet live session → `Done`, none → `Idle`. `Blocked` and `Signaled` are the "needs you" states (`TaskStatus::needs_you`): the watcher notifies on their edge and `sweep` never closes them. **tenx installs no hooks and writes no state of its own**; `tenx hooks install` *removes* the retired v0 hooks. Background agents (`--bg`) run in a subdirectory and are matched by path prefix. The `failed` state was dropped deliberately: the registry can't tell a failed turn from a finished one.
- **The attention watcher** (`cli::watch`): a detached, single-instance process (`~/.config/tenx/watch.pid`) started by `open()`, polling every 2 s (~5 ms per resolve). Two consumers, one resolve pass: a desktop notification on the *edge* into `Blocked` (debounced; tasks already waiting at start are primed as notified; `Done` never notifies — it fires after every turn), delivered via `cli::notify::platform()` (macOS: `terminal-notifier`/`osascript`; Linux: `notify-send`; the mark from `docs/logo/tenx-mark-256.png` is embedded and written to `~/.config/tenx/tenx.png` as the icon, `cli::notify::icon_path`); and `push_status`, which sets `@tenx_status` on each open task window (glyph from `TaskStatus::glyph`, 🔒 when secrets are pending, the bold title, the workspace name muted, then the row's PR/port chips) and the global `@tenx_right` — counting only tasks *other than the current window's*, with `Done` gated on 60 s unanswered so the corner doesn't flicker with every turn you type — only when the digest or the live cache changes, so a quiet session sends nothing. Secrets-pending queues are tracked as further independent edges. It also gives every background agent (`--bg`, a non-interactive session under a task) a 12-line pane in its task's window, once per (cwd, pid), running `tenx internal agent-log` (`cli::agentlog`) — a compact follower of the agent's transcript that exits with the agent. Exits once the tmux server is gone.
- **`tenx secrets`** (`cli::secrets`): task-scoped credentials via the system `age`/`sops`. Read that module's doc comment before touching it — the invariants (never print a value to stdout; `/dev/tty` reachability decides whether `decrypt`/`set` act or enqueue-and-wait; adopted secrets decrypt outside the worktree and are symlinked in) are the whole design. The no-terminal wait (`wait_for_human`, bounded by `--timeout`, default `DEFAULT_WAIT` = 100 s so a shell tool's 2 min kill never hits first; `--no-wait` to skip) polls the queue and decides fulfilled-vs-withdrawn from output mtimes via `tenx_core::secrets::wait_outcome` — no receipt files. `cancel <name>|--all` (CLI, and `:cancel` in the overlay) only edits the queues.
- **`tenx standup`** (`cli::standup`): prints every `TASK.md` plus user prompts and `git commit`/`git push` calls from `~/.claude/projects/<slug>*/*.jsonl` since the last standup (first `## ` heading in `daily.local.md`, else start of yesterday). Meant to be fed to the `/standup` skill.

## Conventions

- Decision logic goes in `tenx-core` with a test; the binary does I/O.
- Derive state from live sources (disk, the session registry, `tmux list-windows`) rather than recording it; the only tenx-owned per-task files are `.tenx-window-id` (a cache — never act destructively on it, look the window up by slug), `.tenx-pinned`, `.tenx-live.json` (a cache of external facts, written only by the watcher), and the two secrets-pending queues.
- Shell out to the real `git`/`tmux`/`age`/`sops`; never link a library for them.
- Keep `make test` green: clippy runs with `-D warnings`.
